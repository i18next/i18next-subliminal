### 2.0.0

- BREAKING: new invisible markers, about a fifth as long (a short key took 684 invisible characters, now 141), made of U+2060 (word joiner) and U+2061-U+2064 instead of zero-width (non-)joiners. They allow no line break, and the start marker leaves Arabic letters joined (the old markers broke the joining at both ends of a translation inside an Arabic word, now only the end marker does). They are the same on the server and in the browser: before, a text wrapped on the server used U+200B/U+200C and could not be read in the browser. A reader older than 2.0 does not see the new markers, so upgrade what reads them (the locize InContext editor 4.8.0 or later) together with this package. Markers written by older versions in a browser are still read; the old server set is not.
- feat: `unwrapAll(text)` returns every wrapped text in a string (two translations joined into one text node, for example) with where it starts and ends, so one of them can be replaced.
- BREAKING (types): `unwrap` was typed as returning a string; it returns `{ text, invisibleMeta }`, as it always did at runtime. `Unwrapped` and `UnwrappedSegment` are exported.
- fix: the post-processor kept the options of the first `t()` call and read them for every later call (only where i18next does not pass the resolved key, before `postProcessPassResolved`), and took the language from a field that was never set. It reads each call's options and the translator's language now.
- `wrap(text)` without meta still adds markers; their meta now reads back as `{ key: undefined, ... }` instead of not at all. `unwrap(null)` returns `{ text: null }` instead of throwing.
